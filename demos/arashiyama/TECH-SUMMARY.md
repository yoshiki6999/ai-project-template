# 「四格岚山」技术方案总结与实施复盘

> 对应版本：Artifact v3（2026-11-27 11:48 UTC 发布，版本号 1795780085-5b81）
> 源代码：本仓库分支 `claude/great-galileo-141nxe`，提交 `3491d24`，目录 `demos/arashiyama/`
> 本文写于 2026-11-27，依据三份材料：① 已发布页面的完整源码；② 原制作会话「Opus 5.6 代码动画能力」的完整记录；③ 本次在云端容器里重新构建、重新运行的验证结果。

---

## 0. 结论先行

1. 这是一个**单文件 HTML 动画**：同一个岚山秋景，切成四条竖格，用四种「代码画风」同时实时渲染。不用图片、视频、后端，也不收集用户数据。
2. 核心设计是 **"一份共享世界描述 + 四个可插拔画格"**：`core.js` 定义场景、镜头和时间函数，每个画格只负责"怎么画"。2D 投影公式与 Three.js 相机在数学上完全一致，所以分隔线两边能严丝合缝对上。
3. 现状是**三格完成**（Motion Canvas 风、Three.js、Blender 风），**Python 风一格未写**（文件不存在，页面显示占位）。另有 2 个本次新发现的小缺陷，见 §9。
4. 最大的技术风险是**性能**：Blender 风一格的渲染开销约为 Motion 格的数百倍，手机上可能发热掉帧，应先做"按设备分级"。
5. 后续开发路线已经很清楚：先补 Python 格 → 做性能分级 → 把 `core.js` 抽成"场景描述 + 部件库 + 画风渲染器"的引擎 → 需要时做逐帧导出视频。

## 2. 技术选型总表

| 层 | 采用技术 | 选它的原因 / 说明 |
|---|---|---|
| 页面形态 | 单个自包含 HTML（Artifact） | 用户在户外用手机看，要求"直接发链接"；Artifact 无需部署、打开即用 |
| 2D 渲染 | Canvas 2D（Canvas 2D API：浏览器自带的画布绘图接口） | 前两格都是平面画风，浏览器原生能力足够，零依赖 |
| 3D 渲染 | Three.js 0.160.0（WebGL 封装库：让浏览器调用显卡画 3D 的工具库） | 业界最常用的网页 3D 库；后两格都用它 |
| 库的加载 | ES Module 动态 `import()`，来自 cdn.jsdelivr.net，版本锁死 0.160.0 | 只在需要 3D 的画格里加载；锁版本避免上游更新破坏页面 |
| 字体 | Google Fonts（Noto Serif SC、Caveat Brush、Fredoka、Inter Tight、JetBrains Mono） | 每格标签用不同字体强化"画风"差异；加载失败有系统字体兜底 |
| 随机数 | mulberry32 带种子伪随机（固定种子的随机数生成器：每次运行结果完全相同） | 保证每帧可复现，截图测试和逐帧导出都依赖这一点 |
| 噪声 | 值噪声（value noise）+ 分形叠加（fbm：多层不同尺度噪声叠加，产生自然的起伏纹理） | 山脊轮廓、红叶配色分布、水面波纹 |
| 动画驱动 | 纯时间函数 `f(t)` + `requestAnimationFrame` | 所有物体位置只由时间 t 决定，可暂停、可跳到任意时刻、可逐帧导出 |
| 构建 | 自写 Node 脚本 `tools/build.cjs`（19 行） | 把多个 `src/*.js` 内联进一个 HTML，不引入打包工具（符合"最简方案"原则） |
| 测试 | Playwright 1.63（浏览器自动化工具：用程序操控浏览器打开页面、截图）+ Chromium SwiftShader（软件模拟显卡） | 云端容器没有显卡，只能用软件渲染截图做目视检查 |
| 开发方式 | Claude Code 云端会话 + Workflow 多代理并行 | 四个画格互相独立，适合分给不同代理并行写 |

## 3. 系统架构

```
index.html（舞台、控件、说明文字）
   │
   ├── core.js ──────────────── 共享层（所有画格都依赖它）
   │     ├─ U   工具函数：插值、缓动、噪声、Catmull-Rom 曲线、颜色
   │     ├─ P   调色板：11 月下旬晴天岚山的 46 种颜色
   │     ├─ 镜头：baseCamera + cameraAt(t)（随 24 秒周期轻微摆动）
   │     ├─ makeProjector()：3D 世界坐标 → 屏幕像素（与 Three.js 相机完全一致）
   │     ├─ S   世界描述：山脊、桂川、渡月桥、树、房屋、竹林、枫枝、云……
   │     ├─ 演员函数：rickshaw(t) / boat(t) / birds(t) / heroLeaf(t) / ambientLeaves(t) / ripples(t)
   │     └─ 舞台引擎：画格注册、时钟、分隔线、单看、键盘、URL 参数、失败兜底
   │
   ├── panel-python.js   （缺失）  Canvas 2D 颗粒笔触
   ├── panel-motion.js   Canvas 2D 矢量描边 + 缓动曲线卡片
   ├── panel-three.js    Three.js 低多边形 + 反射 + 辉光
   └── panel-blender.js  Three.js 柔光渲染 + 阴影 + 环境光照
```

### 3.1 共享世界描述（对齐的关键）

- **坐标系**：右手坐标系，单位约等于米。x 向右，y 向上，z 朝向观众。水面 y = 0。镜头在 (0, 6, 46)，看向 (0, 5.2, 0)，视角 36°。
- **场景分层**（由远到近）：远山 z=-110 → 岚山 z=-42 → 雾带 → 对岸树林、房屋 z≈-15~-27 → 桂川 → 渡月桥 z=0 → 屋形船 z=13 → 近岸、石灯笼、竹林、前景枫枝 z≈26~38。
- **山脊**：用"基准高度 + 若干高斯隆起 + 少量噪声"的公式描述，任何画格调用 `S.ridgeHeight(ridge, x)` 都得到同一条轮廓。
- **红叶配色**：`S.foliageKind(x, y)` 用两层噪声把山坡分成松、杉、深红枫、红枫、橙枫、银杏，四格的山色分布一致。
- **主角红叶的路径**：在"屏幕比例坐标 + 深度"里写 11 个关键点，转换成世界坐标后用 Catmull-Rom 曲线（一种穿过所有控制点的平滑曲线）连起来。前 6% 时间挂在枝头，6%–80% 飞行，之后漂在水面并逐渐淡出。
- **所有演员都是时间的纯函数**：输入 t，输出位置、角度、透明度，没有内部状态。所以暂停、跳帧、四格同步都很自然。

### 3.2 2D 与 3D 的数学对齐

`A.makeProjector(cam, W, H)` 手写了透视投影：先算相机的前、右、上三个方向向量，再按 `H / (2·tan(fov/2))` 求焦距。它与 `THREE.PerspectiveCamera(fov, W/H)` 加 `lookAt(target)` 的结果逐像素一致。这样 2D 画格画出的桥墩和 3D 画格渲染的桥墩落在同一位置。原会话专门用"2D 红线对 3D 蓝线，split=0.5"做过对齐测试，结果通过。

它还提供两个反向函数：`groundAt()`（屏幕点 → 水面上的世界点）和 `atDepthZ()`（屏幕点 + 深度 → 世界点）。用途是在屏幕上直接写位置，以及裁剪反射渲染的范围。

### 3.3 画格接口约定

每个画格调用一次 `ARASHI.registerPanel(def)`：

```js
ARASHI.registerPanel({
  id: 'python' | 'motion' | 'three' | 'blender',
  needsThree: true | false,          // true 时由 core 动态加载 three.js 后再 init
  init(api)  { /* api = { canvas, THREE, S, U, P, A, id } */ },
  resize(W, H, dpr) { /* 舞台尺寸或像素比变化时调用 */ },
  frame(st)  { /* 每帧调用 */ },
});
```

`frame(st)` 收到的状态对象：

| 字段 | 含义 |
|---|---|
| `t` / `dt` / `p` | 累计秒数 / 帧间隔（暂停时为 0）/ 在 24 秒循环中的进度 0–1 |
| `W` `H` `dpr` | 舞台 CSS 像素尺寸、像素比（全局上限 2） |
| `cam` | 本帧镜头（含摆动） |
| `project` `groundAt` `atDepthZ` | 本帧的投影函数 |
| `horizonY` | 地平线的屏幕 y |
| `view` | `{x0, x1}`：本画格当前可见的横向像素范围（用于只画这一条） |
| `paused` `frame` | 是否暂停、帧号 |

画格只要遵守这份约定，就能独立开发、独立替换。某一格抛异常时，core 会捕获错误，在该格显示"这一格没能加载出来"，其他格照常运行。

### 3.4 舞台与交互

- **分格方式**：四个画格的画布都铺满整个舞台，用 CSS `clip-path: inset(...)`（裁剪路径：只显示元素的一部分）只露出各自那一条。可见宽度小于 0.5 像素的画格整帧跳过。3D 画格还用 scissor（剪裁测试：让显卡只处理指定矩形内的像素）只渲染可见条带，省掉大部分开销。
- **分隔线**：可拖动，用 pointer capture（指针捕获：拖动时即使手指移出元素也能持续收到事件），支持方向键微调。标注了 `role="separator"`，读屏软件可以识别。
- **单看模式**：点任意一格，或按数字键 1–4，用 0.85 秒的缓动动画把这一格展开到全宽；再点一次，或按 0 / Esc，回到四格。
- **开场动画**：先全屏显示第一格，0.9 秒后三条分隔线依次滑入。
- **省电**：舞台滚出屏幕时停止渲染（IntersectionObserver：浏览器自带的"元素是否在视口内"监听器）。系统开启"减少动态效果"时，默认暂停在第 9 秒。
- **手机适配**（原会话针对"户外手机看"做的）：舞台铺满屏宽，标签改用短名，横屏时舞台占满屏幕高度，iPhone 上隐藏全屏按钮，标签字号随舞台宽度缩放（容器查询 `cqw`）。
- **URL 参数**：

| 参数 | 作用 |
|---|---|
| `?t=10` | 跳到第 10 秒 |
| `?paused` | 暂停 |
| `?nointro` | 跳过开场动画 |
| `?solo=blender` | 直接单看某一格 |
| `?split=0.25,0.5,0.75` | 指定三条分隔线位置 |

- **测试钩子**：`window.ARASHI_READY`（所有画格就绪后置 true）、`ARASHI.stats()`（每格平均帧耗时，单位毫秒）、`ARASHI.getSplit()`。

## 4. 各画格实现要点

### 4.1 Python 风（未完成）

- **设计意图**：Canvas 2D，模仿用 Python（numpy / PIL）逐像素生成的颗粒手绘质感。标签用 Caveat Brush 手写字体加金色下划线。原会话明确说过"Python 风其实不是真的 Python"，它是用 JS 模仿那种画面效果。
- **现状**：`src/panel-python.js` 不存在。构建脚本输出 `<!-- missing src/panel-python.js -->`，页面上这一格显示"这一格暂未制作"。

### 4.2 Motion Canvas 风（Canvas 2D 矢量动效）

由主会话手写，424 行。

- **平涂 + 粗描边**：统一描边色 `#1d2635`。云朵的描边做法是先画一圈半径加线宽的深色圆，再在上面盖浅色圆，不需要计算轮廓。
- **静态层预渲染**：远山、岚山、对岸三层在 `resize` 时各画到一张离屏画布上，四周各留 6% / 5% 的边距。每帧只用 `drawImage` 贴图，再按镜头摆动的位移做视差偏移（视差：远处物体移动得比近处慢，产生纵深感）。这是这一格每帧只要约 1 毫秒的原因。
- **动效图形叠加层**：
  - 主角红叶的飞行轨迹画成黄黑双层虚线，`lineDashOffset` 随时间流动，起点跟着叶子推进。
  - 一张带窗口按钮的 `easeInOutCubic` 缓动曲线卡片，曲线上的小圆点实时跟随人力车进度，下方显示 `rickshaw.x` 数值。出场时用弹性缓动（outElastic）弹出。
- **枫叶**：7 裂叶片用一个 `Path2D` 路径定义一次后反复使用；用 y 方向缩放 `0.25 + 0.75·|flip|` 模拟叶子翻转。

### 4.3 Three.js（低多边形 · 实时 3D）

由 Three.js 制作代理编写，1,121 行。

- **低多边形质感**：全部使用 `flatShading`（平直着色：每个三角面一个颜色，不做平滑过渡）。自写 `Builder` 把三角面逐个累积成一个非索引几何体，每个面带自己的颜色，最后合并成一个网格，减少绘制调用。
- **大量实例化**：树、草（950 棵）、落叶（300 片）、竹节、桥墩、岩石都用 `InstancedMesh`（实例化网格：同一个模型一次绘制成百上千份，只有位置、角度不同）。
- **植被摆动**：通过 `onBeforeCompile` 给 Three.js 自带材质的顶点着色器注入代码，在世界坐标里按正弦叠加摆动。草、竹子、竹叶、枫叶各有一套参数。
- **水面反射**：把相机按水面镜像，开一个半分辨率的离屏渲染目标，用裁剪平面去掉水面以下的物体，只渲染可见条带附近的范围。水面着色器读取这张反射图，再按每个三角面做扰动。
- **水面效果全在着色器里计算**：太阳闪光（朝向太阳反射方向的三角面会闪烁）、主角红叶落水的涟漪、船体周围泡沫、开尔文尾迹（船行驶时身后呈 V 字形展开的水波）。
- **主角红叶特效**：
  - 叠加混合的发光尾带（ribbon，150 个采样点，取"当前时间往前推 k 个时间步"的位置，而不是记录历史，所以仍是时间的纯函数）。
  - 火花粒子（68 个发射槽 × 3，每个槽的出生时间固定，保证帧与帧之间连续）。
  - 230 颗漂浮光尘。
- **选择性辉光（Bloom：让亮的东西周围泛光）**：只把发光物体（图层 2）以 1/4 分辨率渲染一遍，做两级可分离模糊，再叠加回画面。
- **暂停优化**：暂停且画面参数不变时直接跳过渲染（`lastKey` 缓存）。
- **其他**：线性雾 75–380 米；像素比上限 1.75。

### 4.4 Blender 风（柔光渲染 · Three.js 实时 3D）

由 Blender 制作代理编写，1,325 行，是最重的一格。

- **色调与光照**：
  - ACES 电影色调映射（tone mapping：把高亮度范围压缩到屏幕能显示的范围，ACES 是电影行业标准曲线）。
  - 一盏暖色太阳光，加 2048×2048 的 PCF 软阴影（阴影边缘柔和的阴影算法）。阴影相机的范围按前景和桥紧密包围，提高阴影清晰度。
  - 用程序生成的渐变天空，经 PMREM（预过滤环境贴图：把天空预先模糊成不同粗糙度对应的版本）做基于图像的环境光照，让物体被天空的颜色照亮。
- **统一的着色器补丁 `patch()`**：给所有标准材质注入同一套代码：
  - 世界坐标与时间；
  - 自定义空气透视雾和两条山脚雾带。雾在色调映射之后混合，保证远景正好褪成调色板里的雾色。
  - 按法线朝向做的伪环境光遮蔽（AO：缝隙和背光处更暗）；
  - 树冠边缘的透光，作为次表面散射（光线穿透叶片的效果）的廉价替代；
  - 草、芒草、竹子、竹叶、枫枝各自的风动。
- **云朵**：实例化球体组成的蓬松云，球与球之间用解析公式计算遮挡（不需要真正的光线追踪），上缘加小鼓包形成"花椰菜"质感。
- **水面**：平面镜反射，用半分辨率、半精度浮点（HalfFloat）的渲染目标。用"斜近裁剪面"技巧把水面以下的物体裁掉。只渲染可见条带能采样到的那部分反射图。水面法线来自三层噪声，并叠加涟漪、船尾迹、桥墩泡沫。
- **细节物件**：倒角石灯笼、长青苔的岩石、物体接地处的接触阴影、7,600 片实例化草叶（约 14% 为枯黄色）、芒草穗、带光泽会摇摆的竹林、前景枫枝、空中浮尘。
- **性能参数**：像素比上限 1.5；反射分辨率 0.5 倍；阴影图手动控制更新（镜像渲染沿用上一帧的阴影图）。

## 5. 构建与发布流程

```
demos/arashiyama/
├── index.html          开发页；<!--ARTIFACT:START--> 与 <!--ARTIFACT:END--> 之间是要发布的内容
├── src/core.js
├── src/panel-*.js
├── tools/build.cjs     内联构建 → dist/arashiyama.html
├── tools/shoot.cjs     截图与性能测试
├── package.json        devDependencies: three@0.160.0（只给本地测试用）
└── .gitignore          node_modules/（dist/ 也未提交）
```

1. **开发**：直接编辑 `src/*.js`。`index.html` 用 `<script src="src/xxx.js">` 引用。
2. **构建**：`node tools/build.cjs`。截取标记之间的内容，把每个 `<script src>` 替换成内联代码，并加上 `/* src/xxx.js */` 注释头。文件缺失时留下注释并告警。如果 JS 里出现 `</script` 字样就报错，因为它会提前结束内联脚本。
3. **语法预检**：原会话在构建前用 `node -e "new Function(...)"` 检查每个文件能否解析。

## 9. 已知问题与技术债

| # | 问题 | 影响 | 建议修法 |
|---|---|---|---|
| ① | **`ARASHI_READY` 永远不会变成 true**（本次发现）。`tick()` 要求 `PANEL_ORDER` 里每个画格都已注册且 ready 或 failed，而 Python 格从未注册 | 自动化测试只能靠超时；以后接逐帧导出时会卡住 | 只统计已注册的画格，或在启动若干秒后把未注册的画格视为 failed |
| ② | **暂停时 Motion 格和 Blender 格仍然每帧重画**（本次发现）。只有 Three.js 格有 `lastKey` 缓存 | 暂停状态下手机仍然发热、耗电 | 把"暂停且视图不变就跳过"的逻辑上移到 core 的 `tick()`，所有画格统一受益 |
| ③ | Python 格未实现 | 四格变三格；页面说明文字仍在介绍 Python 风 | 见 §10.1 |
| ④ | Blender 格太重 | 手机可能发热、掉帧 | 见 §10.2 |
| ⑤ | 两个 3D 画格各自创建一个 WebGL 上下文，场景也各建一份 | 显存和内存占用翻倍 | 引擎化时考虑共用一个 renderer，用 scissor 分区渲染 |
| ⑥ | 运行时依赖 jsdelivr CDN 和 Google Fonts | CDN 不可用或离线时两格 3D 失效（有兜底提示），字体降级 | 需要离线或长期保存时，把 three.js 精简后内联，或改用 Artifact 资源存储 |
| ⑦ | Blender 格水边有白色星形小物件，远山偏灰 | 画面瑕疵 | 美术复查时修 |
| ⑧ | 拖动、键盘、单看等交互没有自动化测试 | 回归风险 | 在 `shoot.cjs` 里加 Playwright 交互用例 |
| ⑨ | `dist/` 没有提交，`docs/STATUS.md` 没有更新 | 换会话时缺少状态记录 | 每次发布后更新 STATUS |

## 10. 后续开发指南

### 10.1 补完 Python 格（优先级最高）

1. 新建 `src/panel-python.js`，按 §3.3 的接口约定注册：`id: 'python'`，`needsThree: false`。
2. 画风目标：模仿 numpy / PIL 逐像素生成的效果。可以这样做：
   - 在 `resize` 时按 1/2 或 1/3 分辨率建一个 `ImageData` 缓冲；
   - 用 `S.ridgeHeight`、`S.foliageColor`、调色板逐像素着色，叠加噪声颗粒和抖动（dithering：用交错的点阵模拟中间色）；
   - 静态背景像 Motion 格一样预渲染缓存，动态物体（船、人力车、叶子）每帧单独画；
   - 用 `putImageData` 输出后放大，保留像素颗粒感。
3. 只画 `st.view` 范围内的像素，控制开销。
4. 运行 `npm run verify`，检查分隔线两侧是否对齐。
5. 顺便修 §9-①，让 `ARASHI_READY` 能正常变为 true。

### 10.2 性能分级

- 启动时根据 `navigator.hardwareConcurrency`、屏幕尺寸、首几帧的实际帧耗时，自动选择"高 / 中 / 低"三档。
- 低档：Blender 格关闭阴影和反射，降低像素比，草叶数量（目前 7,600 片）减半；Three.js 格关闭辉光。
- 再配合 §9-② 的暂停跳帧，能明显降低手机发热。

### 10.3 引擎化（原会话给出的规模化路线）

把 `core.js` 拆成三层：

```
场景描述（JSON / JS 数据）  ←  换城市、换季节只改这里
        │
部件库（桥、船、树、人物、动作……）  ←  各画风共用的语义部件
        │
画风渲染器（python / motion / three / blender / …）  ←  只负责"怎么画"
```

这样"京都导览系列"或"日语短剧动作演示"就变成"写一份新的场景描述，挑画风"，不必每次从零开始。

### 10.4 逐帧导出视频

所有画面都是时间 t 的纯函数，而且随机数带固定种子，天然支持逐帧导出：

1. 用 Playwright 循环 `?t=0, 1/30, 2/30…&paused&nointro` 逐帧截图（或在页面里调用 `canvas.toBlob`）；
2. 用 ffmpeg 合成 MP4，用于 YouTube、Instagram 等平台；
3. 云端没有显卡、渲染慢，需要大量出片时可以放到带显卡的云服务（原会话提到 GitHub Actions 加 Modal）。

### 10.5 换场景复用

- 改调色板 `A.palette` 和 `S.*` 里的地形、建筑参数，就能换成其他景点。
- 主角路径 `heroKeys` 用"屏幕比例 + 深度"编写，可以直接按构图需要调整。
- 画格接口不变，已有的三个渲染器可以直接复用。
